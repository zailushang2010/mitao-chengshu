# 产品生命周期：DEFINE → PLAN → BUILD → VERIFY → REVIEW

适用于 **蜜桃成熟** 及本仓库一切功能、修复、重构。  
目标：少碰运气、可验收、可回溯。

---

## 1. DEFINE（定义）

回答：「我们要解决什么？做完什么样算对？」

### 必写内容

| 字段 | 说明 |
|------|------|
| 问题 | 用户痛点 / 缺陷现象 |
| 用户与场景 | 谁、在什么时候用 |
| 范围内 | 本次要交付的行为 |
| 范围外（非目标） | 明确不做，防蔓延 |
| 约束 | 平台、PotPlayer、性能、安全等 |
| 验收标准 | 可勾选、可复现的条目（Given/When/Then 或检查表） |

### 落盘

- 产品基线：`docs/product/DEFINE.md`（持续更新）
- 单次大改可另建：`docs/product/changes/YYYY-MM-DD-短名-DEFINE.md`

### 完成条件

- 验收标准无歧义，实现方与验收方理解一致
- 非目标写清楚

---

## 2. PLAN（计划）

回答：「怎么做？先做什么？风险在哪？」

### 必写内容

| 字段 | 说明 |
|------|------|
| 方案要点 | 1～3 种可选时写清取舍 |
| 任务拆分 | 有序、可并行处标明 |
| 涉及模块 | 文件 / 子系统 |
| 风险与回退 | 尤其是 PotPlayer 行为、多开、配置兼容 |
| VERIFY 预告 | 准备跑哪些命令、哪些手测 |

### 落盘

- 滚动计划：`docs/product/PLAN.md`
- 大任务可：`docs/product/changes/…-PLAN.md`

### 完成条件

- 任务粒度适合一次 BUILD（避免「重构整个 app」式空包）
- 不开始写核心逻辑前 PLAN 已确认（或用户明确「按此执行」）

---

## 3. BUILD（实现）

回答：「按计划改代码。」

### 规则

- **只做 PLAN 内事项**；发现范围外问题 → 记入 PLAN / 新 DEFINE，不偷偷膨胀
- 小步提交，说明「做了什么、为何」
- 遵守 `AGENTS.md` 与 UI skill，不引入无效控件（如无音量注入却做滑条）

### 完成条件

- 代码可编译；计划内行为已实现或明确未完成项

---

## 4. VERIFY（验证）

回答：「有证据证明对了。」

### 最低要求

```text
cargo test
cargo build --release
```

### 按变更类型追加手测

| 类型 | 手测示例 |
|------|----------|
| 片库/配置 | 增删目录、重启后仍在、坏 json 不瞎造路径 |
| 随机预览 | 数量、避开最近、剔除、再来一批不自动播 |
| 电影开播 | 多开 N 部入格、无整窗跳出、关闭本轮只杀本工具实例 |
| 图片 | 幻灯/墙、Esc、与后台电影并存 |
| 模式切换 | 不 thrash 窗高、park/恢复 PID |

### 落盘（推荐）

- 在提交说明或 `docs/product/VERIFY-log.md` 追加日期 + 结果
- 失败则回到 BUILD 或修正 DEFINE

### 完成条件

- 命令有结果；相关手测项全部勾完或标注阻塞原因

---

## 5. REVIEW（回顾）

回答：「对照定义是否达标？留下什么？」

### 检查清单

- [ ] 验收标准是否全部满足？
- [ ] 是否引入 DEFINE 范围外的行为？
- [ ] 用户可见文案/配置是否与实现一致？
- [ ] 已知限制是否写进 DEFINE「已知限制」？
- [ ] PLAN 是否更新（完成 / 延期 / 新增）？
- [ ] 是否需要 bump 版本与打包？

### 完成条件

- DEFINE / PLAN 文档与代码现状一致
- 未达标项有明确后续条目

---

## 与紧急修复（hotfix）的关系

线上级严重问题可先 BUILD 止血，但必须在 **同一工作周期内** 补：

1. DEFINE（现象 + 验收）
2. PLAN（根因与正式方案）
3. VERIFY 证据
4. REVIEW 是否还需根治

纯「延后重试碰运气」类方案若验收仍不稳，REVIEW 必须升级为根因 PLAN（本产品平铺问题已按此要求演进）。

---

## 角色建议

| 角色 | 侧重 |
|------|------|
| 产品/用户 | DEFINE 验收、非目标 |
| 实现 | PLAN + BUILD |
| 验证 | VERIFY 不手软 |
| 回顾 | REVIEW 更新文档与版本 |

一人开发时：五阶段仍要走完，可压缩篇幅，**不可省略门槛**。
